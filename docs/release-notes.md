v1.3.3
======

修复
----

* 启动时同时释放 x64 + x86 DLL。之前只释放 x64，导致首次跨位数注入时报
  "x86 DLL 未内嵌也未编译"；资源提取、内存快照、查看/修改也都被这道闸门
  挡住。现在 exe 启动时把两份 DLL 都校验并写到磁盘。
* ``dll_for_arch("x86")`` 在内嵌可用但磁盘缺文件时自动落盘，避开「自检时
  还没用到 x86」与「真正用的时候才落盘」之间的时序问题。

新增
----

* 设备访问面板（lsof 视角）。在 GUI 进程表选中目标后点「刷新」，会枚举目标
  进程打开的句柄，按 Win32 对象类型归到中文大类（文件 / 管道 / 设备 / 网络
  / 注册表 / 同步 / 进程/线程 / 内存 / GUI / Other），每条带句柄值、类型、
  对象名、访问掩码。
* CLI 子命令 ``SuperInject handles <pid>``，支持 ``--category`` 过滤分类、
  ``--name-contains`` 按对象名过滤、``--limit`` 限条数。
* MCP 工具 ``list_handles``（read 档，授权会话可直接调用）。

## 使用前必读

本工具仅供开发人员调试程序使用，严禁滥用，违规使用者后果自负。

- 只能用于你自己拥有、或已获得明确授权的目标进程；
- 严禁用于绕过软件的授权 / 保护机制；
- 未经授权对第三方进程注入 DLL 可能违反当地法律与服务条款，由此产生的一切后果由使用者自行承担。

## 验证情况

windows runner 上用 MSVC 构建注入端 DLL（x64 + x86），并在真实 Windows 进程里跑集成测试：注入、内存读写、冻结、快照对比、断点、资源导出、卸载、重新注入。打包产物另外跑一遍全链路自检。

设备访问面板的句柄枚举在 Windows 真实机器上验证；macOS 单元测试覆盖分类逻辑与协议层。

界面交互、句柄枚举的完整覆盖（设备 / 命名管道 / 注册表键 / 同步对象）需要你在真机上确认。
